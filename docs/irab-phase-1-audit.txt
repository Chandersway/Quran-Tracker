MAPPING FINDINGS
Endpoint: /v1/ayah/{surah}/{ayah}/book/316 uses local Hafs verse references.
Actual content.ayahs values are global IDs in this sample, despite the docs'
illustration of a local range string. Examples: 2:1 -> 8..12; 2:255 ->
262,263,264; 2:282 -> 289; 114:6 -> 6231..6236.
Validate IDs using canonical Hafs counts; NEVER interpret 262 as local verse 262
when requesting 2:255. Don't trust ayahs metadata as exact text boundaries:
page 108 also begins with the continuation of the preceding ayah's explanation.
HTML contains p/br/div and footnotes. Sanitize rendering, disable scripts and
remote resources, retain paragraphs and footnotes; don't inject arbitrary HTML.
Combining consecutive returned pages is needed for 2:282. Automatic trimming
on a header alone risks removing continuation text. Preferred first UI:
'Book excerpt related to this ayah; may include surrounding ayahs', with source,
volume/page and unchanged original text. Precise extraction is a later feature.

USAGE POLICY CHECK (provider statement, not independent rights clearance)
Live API: free for apps, no authentication. Attribution optional for live use;
we should still visibly credit Quranpedia and the specific book.
Published rate limits: 120 requests/min/IP and 10,000/day/IP; handle 429 and
avoid retries in a tight loop. No mass API scraping. Official versioned dumps
and a changes endpoint are offered for bulk data; dataset republication requires
Quranpedia attribution/link. Avoid frozen unmaintained copies.
Use live fetching for phase 2. Offline redistribution/update strategy and any
book-specific restrictions need separate review before bundling book content.

WARSH
Do not call the explanation Warsh-specific. Existing Warsh-to-Hafs verse mapping
can locate corresponding references but does not resolve grammatical differences
between readings. Keep phase 2 Hafs-based; verify Warsh separately in phase 4.
