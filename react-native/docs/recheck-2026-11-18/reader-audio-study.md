# Reader, audio and study parity recheck — 18 November 2026

This pass compared the original Kotlin implementation with the current React Native implementation, reproduced concrete differences, and repaired four of them. The comparison used original code and source assets, not the prior parity report as proof. It did not modify source Quran text, translations, artwork, book databases, edition geometry, import scripts, user data, or remote accounts.

The resulting evidence is **147 passing scoped tests**, a passing TypeScript check, a passing focused ESLint check, an independent comparison with the original content, and read-only requests through the actual study-provider service. These are source, data, domain and component-level results. This pass did not run either app on an Android or iOS device, and does not claim device rendering or background audio verification.

## Deliberate mappings and remaining boundaries

- A separate original translation screen is represented by the RN text reader, page-translation sheet and source-context translation. Arabic, NL and EN source content remains intact. General source loading uses the existing explicit Load action; restored tafsir previous/next actions also load the selected verse.
- Warsh rub navigation now supports an on-demand page. The original requirement to install all 604 pages before opening a rub is not a missing capability. The guide's statement that a full download may first be required was reported to the root reviewer for correction.
- `warsh_quran_world` appears in old crop code, but the active original route migrates that old preference to a supported edition. Its mere presence in old helpers is not evidence of a missing selectable library entry.
