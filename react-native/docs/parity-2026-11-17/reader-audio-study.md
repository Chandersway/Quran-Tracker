# Reader, audio, and study parity audit — 2026-11-17

Scope: requested sections 1, 2, 3, 14, 15, 19, plus the audio/media settings portion of section 20. Audit only. No app/source files, native user data, or cloud state were modified. Supporting files in `.tooling` are audit artifacts.

Authority: the sibling Kotlin source and its active callers, compared with current RN source. Old documentation and tests were not treated as the behavior specification. No applicable `AGENTS.md` was found in this workspace or its project ancestors. This was source/data inspection, not a native-device or live-provider test. Root owns full verification; I did not repeat it.

Status terms: **present** means a reachable implementation was traced; **partial/mismatch** means related functionality exists but behavior differs; **missing** means no alternate implementation was found in the stated search scope; **intentional interaction change** acknowledges the user's later selection-toggle/unified-menu direction; **historical only** means Kotlin code exists but current normal entrypoints do not reach it. “Present” is not a claim that native behavior was exercised.

## Material findings

1. **Warsh rub navigation uses Hafs start points despite preserving the verified Warsh data.** 56/240 canonical references and resolved Warsh destinations differ; 18/240 land on another page. Example rub 40 (hizb 10, quarter 4): RN canonical `4:135` resolves to page 100, printed Warsh 134; Kotlin canonical `4:130` resolves to page 99, printed Warsh 129. These are separate numbering systems, not an alleged constant offset. Kotlin's actual canonical route was compared, and all 240 Kotlin resolutions agree with its validated boundary rows. Evidence and all rows: `.tooling/parity-2026-11-17-warsh-rubs.py` and `.tooling/parity-2026-11-17-warsh-rubs.json`.
2. **Global Quran ayah search is missing.** Kotlin searches Arabic ayah text across the Quran from its main reader list. RN's main Quran search filters surah metadata; text/translation search is limited to the currently opened surah/range.
3. **Changing a reciter resets playback and unpauses it.** Kotlin preserves playback time and existing playing/paused state when choosing a reciter. RN's reciter row calls ordinary `play`, which clears paused state and seeks to zero. There is also no separate “choose without starting” action or name/riwaya filter.
4. **A merged printed Warsh selection is truncated by copy/share and word-details actions.** RN displays all linked canonical verses, but constructs the copied/shared text from the first only. Kotlin joins all mapped verse texts and word lists.
5. **Active Maknoon and general PDF crop rules are absent from RN.** RN fits the full image/PDF and applies user zoom. Kotlin applies fixed 115% Hafs Maknoon/112% Warsh Maknoon crop zoom, or 5.5% side/4.5% top/5.5% bottom PDF crop before display. The Warsh Quran World odd/even crop code is historical only in the current Kotlin app, and is not counted as an active regression.
